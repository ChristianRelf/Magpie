# Build and release

## Versioning and packages

Keep `Cargo.toml` workspace version, root/package versions and `apps/desktop/src-tauri/tauri.conf.json` in sync. Commit both lockfiles. Append database migrations; never rewrite one after release. Change `API_VERSION` for breaking local API contracts.

`pnpm build` produces installers for the build host. Linux outputs are under `target/release/bundle/deb` and `appimage`; Windows uses NSIS; macOS uses `.app` and DMG. Ordinary use needs no Rust/Node/Docker. The optional `magpie` CLI is built separately with `cargo build --release -p magpie` and can be placed on PATH.

The **Build installers** GitHub workflow builds native packages and the CLI on Linux x64, Windows x64, macOS arm64 and macOS Intel. It runs platform Rust tests and an isolated lifecycle test, then uploads artifacts. It does not publish a release. Use Actions workflow dispatch for a review build. A `v*` tag also triggers packaging; tag only a validated commit.

Build Linux on the oldest supported distribution. The workflow uses Ubuntu 24.04; locally built packages reflect the host's libraries and are not proof of compatibility with every distribution. AppImage may require FUSE support; the standard `--appimage-extract-and-run` fallback can be used where necessary. Test Secret Service access under the actual desktop session, not just a headless CI runner.

## Signing and automatic updates

No production signing/notarisation credentials are present in this repository. Do not describe unsigned or ad-hoc builds as signed public releases. Configure platform signing using [Tauri distribution documentation](https://v2.tauri.app/distribute/), including Apple Developer signing/notarisation and Windows code signing.

The native updater is implemented and verifies update signatures. Without both build-time values below, Settings clearly reports that the update channel is unavailable and manual installation is required:

- `MAGPIE_UPDATE_PUBLIC_KEY`: public key generated by the Tauri signer.
- `MAGPIE_UPDATE_URL`: HTTPS endpoint for the Tauri update manifest.

Generate keys with `pnpm --filter @magpie/desktop tauri signer generate`. Keep the private key/password in release secrets. Build signed updater artifacts with `TAURI_SIGNING_PRIVATE_KEY` and optional `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, passing `--config '{"bundle":{"createUpdaterArtifacts":true}}'` to `tauri build`. Follow the [official updater manifest format](https://v2.tauri.app/plugin/updater/) for platform URLs and signatures. Publish files and the manifest over HTTPS only after verification. Platform installer signing and updater signing are separate.

Update checks honour the user's preference. Installation is explicit from Settings; the harness is stopped before replacing the app. Test an actual version-to-version update on every platform before advertising automatic updates. No release endpoint or credentials have been invented for this project.

## Release verification

- Typecheck, UI/SDK tests, Rust workspace tests, dependency audits and Playwright integration workflow.
- Lifecycle test with the actual built desktop binary: `MAGPIE_TEST_DESKTOP=target/release/magpie-desktop node scripts/lifecycle-test.mjs` (build the debug CLI first, or set `MAGPIE_TEST_BINARY`).
- Linux native-window test (requires Xvfb, xdotool and xwd): `NO_AT_BRIDGE=1 GTK_USE_PORTAL=0 dbus-run-session --config-file=scripts/headless-session.conf -- python3 scripts/native-window-test.py`. The isolated bus avoids activating portals from an unrelated desktop session. This checks the real WebKit window and both close policies.
- Fresh installation, upgrade migration, uninstall, tray/no-tray close behaviour, keep-running opt-in and start-on-login on each platform.
- Real OS credential storage write/read/delete and expired/revoked provider authentication.
- Optional real-provider smoke test with explicit test credentials and consent.
- Keyboard navigation, focus/labels, reduced motion, theme persistence, chart selection/hover, offline states and 900px minimum window layout.
- Verify payload hashes, platform signatures and updater signatures on downloaded artifacts.

See [STATUS.md](STATUS.md) for what has actually been run. Automated fixture execution validates the complete harness path but does not establish real-provider entitlement or installer signing.
